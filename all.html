csv-columns Manual

for Tuatara 0.90.13 and later, every chapter on one page

This manual is written with modal editing on, first and foremost. Where a command also has a key that works with modal editing off, it is given as well, as the non-modal key.

What csv-columns is

The package that rearranges the columns of a CSV or TSV file as awk's print does.

csv-columns adds one command to Tuatara's CSV mode. It reads a list of columns, such as $0,$2,$1"text", and rewrites every record of the buffer to hold those columns, in that order. A column can be a field of the record, a piece of text, or the two joined.

The package does not keep, delete, show or hide records by the value of a column. Tuatara does that itself: C-x / k, C-x / d, C-x / f and C-x / h. They are in the editor's manual.

1.1 Where it works

The command is bound in CSV mode, and so in a buffer of a CSV file or a TSV (tab-separated values) file. The separator is the one the mode found for the buffer, a comma or a tab. In any other buffer the command is not bound.

A record is a line, as CSV mode reads one. A quoted field does not run on over a line end.

1.2 Counting from 0

Columns are counted from 0, as csvdt counts them. $0 is the first column and $1 the second. $* is the whole record, as in csvdt, and $NF is the last column of each record.

1.3 The key

All the package's keys are under C-c r, which Tuatara labels csv-columns in the key help. There is one key so far: C-c r a runs csv-rearrange-columns. Chapter 4 lists it.

Rearranging columns

Asking for the columns, and what comes out.

C-c r a (csv-rearrange-columns) asks Columns from $0 ($0,$2,$1"text"):. Type the columns as awk's print writes them, counted from 0, separated by commas, and press RET. An empty answer changes nothing.

For example, this answer on a file of five columns:

$0,$1,$3,$4"cent","hello"

leaves out the third column ($2), joins cent to the value of the fifth column, and adds a sixth column, now the fifth, that holds hello:

a,b,c,d,e   ->   a,b,d,ecent,hello

2.1 What a column can be

Each column is made of one or more parts, written side by side with nothing between them. Spaces between columns are ignored.

  • $N is column N, counted from 0.
  • $NF is the last column of each record. The last column is not the same number on every record, so $NF follows the record.
  • $* is the whole record. Alone, its columns stay its own, so the record is copied as it is. Joined to other parts, it is one column that holds the record's text as written.
  • "text" is text as it stands. Inside it, \" is a quote and \\ is a backslash.

Parts side by side are joined into one column, as in $4"cent" or $2" "$0, which puts the third column, a space and the first column in one column.

An answer that is not understood stops the command with a message that says where in the answer it went wrong. Nothing is changed. The messages are A $ needs a number, NF or *, A quote is left open and Not understood.

2.2 How a column is written

A column made of one field alone is written exactly as it stood, with its quotes if it had them.

A column joined from parts, or made of text, is written anew. It is put in quotes when it needs them: when it holds the separator, a quote or a line end, or begins or ends with a space. A quote inside it is doubled.

A column that a record does not have is empty, as in awk. The record a,b with the answer $0,$3 comes out as a,.

A byte-order mark at the start of the file stays at the start. It is not part of the first field.

2.3 Which lines

Every line is rearranged, the header too, as awk would. With a selection, only the lines it touches are. A line that comes out as it was is left alone and is not counted as rearranged.

When the command ends, the echo area says how many lines it rearranged. On an empty buffer, or a selection with no lines, it says No records to rearrange.

2.4 Undoing

The whole command is one step to undo, whatever the number of lines. Press u in modal editing, or the undo key of your editing style.

Large files and limits

How the command behaves on a big file, and what it will not do.

3.1 Large files

A large file is rearranged in the background, as a job, on all but two of the computer's cores, so the editor answers while it works. The letter P is lit in the mode line, and C-x j shows how far the job has got. The result is one step to undo, the same as for a small file.

On a file of 11.5 GB with 100 million records, rearranging every record as in chapter 2 took 30 seconds.

3.2 Each record is read once

Each record is read once and the new one is the only thing made. The package measures the new record first and then fills it, so a line of a large file costs no more than the line it becomes.

3.3 Limits

  • A record is a line. A quoted field that runs on over a line end is not one field.
  • Up to 256 of a record's first fields are placed at once. Fields further on are found one at a time, so a column number past 256 works, only more slowly. Nothing in the settings changes the number.
  • The package works only on CSV and TSV buffers, and the columns are numbered from 0, never from 1.

Every command and setting

Each command and setting of csv-columns, to look one up by name.

The tables are made from the program each time this manual is made, so they never list a command or setting that csv-columns does not have. The first table has four columns. The first two are keys: the modal keys, which work only with modal editing on, and the non-modal keys, which work with it off too. A command with no key says M-x and its name in the second column, because you can only run it by its name. The third column is the name of the command and the fourth says what it does.

To run a command by its name, press M-x, type a few letters of the name and press RET. To find a command from within the editor, press C-h f. To find the command that a key runs, press C-h k and then the key. The editor's own settings and commands are in chapters 21 and 22 of its manual.

csv-columns has no settings of its own, so the second table is empty.
